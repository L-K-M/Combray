The `pdfium-wasm` texts cover what `@embedpdf/pdfium` 2.15.1 builds into `pdfium.wasm` and `index.browser.js`. Its build recipe is `packages/pdfium` of embedpdf/embed-pdf-viewer at `eb14d5ae4bdb0626fa8c63ffead6d9e0d74ce2bc`, the commit on the `v2` branch that set version 2.15.1, 43 minutes before the registry published it; no later commit on that branch changes the package. It builds the PDFium fork embedpdf/pdfium at `73a041a5c1aaffa09ebb64f1981ff501cb91a41c` with `pdf_use_skia=false`, `pdf_enable_xfa=false` and `use_custom_libcxx=false`, through `gclient sync` of that fork's `DEPS`, in the `emscripten/emsdk:3.1.70` image. The package does not prove which tree produced its binary, so these revisions are the recipe's, confirmed where the binary allows it (version strings, ICU's case-mapping tables, fast_float's power-of-five table, libjpeg's `jpeg_natural_order`, Abseil's hash multiplier, libc++ and musl error strings).
